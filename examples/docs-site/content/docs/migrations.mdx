<p className="kicker">Change your schema without breaking the content and data you already have.</p>

Sooner or later you rename a field, split one into two, or change its type.
The schema change itself is one line. The work is updating everything already
written in the old shape, so that it still passes the new schema.

A Graft migration is a TypeScript file that does that update. There are two
kinds, depending on where the old data lives:

- A **content codemod** rewrites your Markdown files, for content in Git.
- A **data backfill** updates rows in Postgres, for
  [operational data](/docs/operational-data).

Migrations live in `migrations/<number>-<name>.ts` and run in number order.
Graft records each one it applies in a table called the **ledger**
(`migrations_applied`), so a migration never runs twice. `graft migrate`
only reports what would change until you pass `--apply`.

```sh
graft migrate            # report pending
graft migrate --apply    # run; record in migrations_applied
```

## Content codemods

For file-authoritative collections, change the **files**. Changing only the index
would be overwritten on the next compile.

```ts
// migrations/0001-pages-description.ts
import { defineContentMigration } from "@usegraft/content-migrations";

export default defineContentMigration({
  collection: "pages",
  describe: "backfill description from tagline",
  transform(doc) {
    doc.data.description ??= doc.data.tagline ?? "";
    return doc;
  },
});
```

The migration validates every output against the current schema, rewrites files
in place, and fails all-or-nothing. Review the diff and commit it.

## Data backfills

For db-authoritative collections, use `defineDataMigration` from `@usegraft/core`.
Updates and the ledger row commit in one transaction. A second apply loses the
unique race and becomes a no-op.

## After a rename or delete

Old index rows can look foreign to a new schema. Compile then refuses with
`INDEX_OWNERSHIP`. That is the one legitimate use of
`graft compile --prune-unknown`. Run it once, after the rename lands.

## Merge interaction

`graft merge` replays the ledger onto the target before moving data rows. Content
migrations only record a ledger entry on merge; their file rewrites arrive via
the git merge you do first. See [Branching & previews](/docs/branching-previews).
