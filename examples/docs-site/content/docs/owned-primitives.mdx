A primitive is owned, copy-in code. `graft add comments` drops TypeScript under
`graft/`, regenerates the barrel, and leaves the files yours to edit. There is
no `@usegraft/comments` runtime dependency and no plugin API boundary.

```sh
graft add                # list available items
graft add comments       # copy item + transitive deps into graft/
graft add commerce --dry-run
```

## Wiring

The generated `graft/index.ts` barrel aggregates collections and functions.
Your config merges it once:

```ts
export const { collections, functions } = mergePrimitives([
  { collections: { pages }, functions: { /* project fns */ } },
  primitives,
]);
```

Duplicate keys fail with `CONFIG_INVALID`.

## What ships today

| Primitive | What you get |
| --- | --- |
| `scoped-access` | Named token scopes + access-rule helpers |
| `comments` | Db-authoritative collection + post / list / moderate / delete |
| `seo` | Composable SEO frontmatter fields |
| `callout` | Content block + MDX component |
| `faq` | Structured FAQ fields + block |
| `commerce` | Products (file) + orders (db) + place / list / update / cancel |

Browse before you add:

```text
MCP: list_registry → describe_item
```

## Registry shape

Items live in `@usegraft/registry` as local manifests (`block` / `field` /
`access` / `bundle`). Remote HTTP registries are format-compatible later. Today
the registry is in-repo, versioned with core, and testable.

See [Schema](/docs/schema) for `mergePrimitives` and field nesting.
