<p className="kicker">Render Graft content in a Next.js App Router project, from install to cache refresh.</p>

This guide adds Graft to a Next.js App Router project. By the end, your pages
read typed content in Server Components, render its Markdown with your own
components, and refresh only the pages whose content changed.

**Before you start**, you need a Next.js 14, 15 or 16 project using the App
Router, and a `graft.config.ts` with compiled content. If you have not got
those yet, run through [Getting started](/docs/getting-started) first. It takes
about ten minutes.

What `@usegraft/sdk-next` gives you:

- **Typed reads in Server Components.** Every result is typed from your schema.
- **One read per document per request.** If a layout and a page read the same
  document, Graft reads it once, using `React.cache`.
- **Markdown rendering on the server.** `<MdxBody />` renders a document's body
  without sending an MDX parser to the browser.
- **Targeted cache refresh.** `revalidateContent` refreshes only the pages whose
  content changed.

<Callout label="Prefer to let your agent do it?" type="note">
  Paste this into your coding agent: "Add Graft to this Next.js app following
  https://graft.page/docs/next.md. Put the client in lib/graft.ts and render
  the pages collection at app/[slug]/page.tsx."
</Callout>

## Wrap your Next.js config

Wrap your config with `withGraft`. Today it does one thing: it keeps
`@usegraft/registry` out of the server bundle, because that package reads files
from disk at runtime. Plain content reads work without it, but the
[MCP route](#serve-functions-and-mcp-from-your-app) needs it, so add it now:

<CodeBlock title="next.config.ts">

```ts
import { withGraft } from "@usegraft/sdk-next/config";
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  // your existing Next.js options
};

export default withGraft(nextConfig);
```

</CodeBlock>

`withGraft` reads your installed Next.js version and sets the option that
version expects. Next.js 14 cannot load a TypeScript config, so on 14 put the
same code in `next.config.mjs` without the `NextConfig` type.

## Create the Graft client

Create the client once, in a file only the server imports. Pick the version for
your [storage engine](/docs/tiers).

<Tabs labels="Static, Postgres">

<Tab>

<CodeBlock title="lib/graft.ts">

```ts
import { openStaticIndex } from "@usegraft/db";
import { createGraft } from "@usegraft/sdk-next";
import { collections } from "@/graft.config";

export const graft = createGraft({
  index: await openStaticIndex(".graft/index.db"),
  collections,
});
```

</CodeBlock>

</Tab>

<Tab>

<CodeBlock title="lib/graft.ts">

```ts
import { createDb } from "@usegraft/db";
import { createGraft } from "@usegraft/sdk-next";
import { collections } from "@/graft.config";

export const { db } = createDb(process.env.DATABASE_URL!);
export const graft = createGraft({ db, collections });
```

</CodeBlock>

The Postgres version also exports `db`, because the function and MCP routes
below need it.

</Tab>

</Tabs>

Every read goes through `React.cache`. If a layout and a page both read the
same document during one request, the index is read once.

## Show a document

A page reads its document by slug and renders the body with `<MdxBody />`.
`getContent` returns `null` for a slug that does not exist, so send that to
`notFound()`:

<CodeBlock title="app/[slug]/page.tsx">

```tsx
import { notFound } from "next/navigation";
import { MdxBody } from "@usegraft/sdk-next";
import { graft } from "@/lib/graft";

// Optional: build every page ahead of time.
export async function generateStaticParams() {
  const pages = await graft.listContent("pages");
  return pages.map((page) => ({ slug: page.slug }));
}

export default async function Page({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  const page = await graft.getContent("pages", slug);
  if (!page) notFound();

  return (
    <article>
      <h1>{page.data.title}</h1>
      {page.data.tagline && <p>{page.data.tagline}</p>}
      <MdxBody source={page.body} />
    </article>
  );
}
```

</CodeBlock>

`page.data` is typed from the `pages` collection in your schema, so a misspelled
field is a compile error, not an empty heading.

## Use your own components in Markdown

Pass `components` to `<MdxBody />` to render a tag in your content with your
own React component. This content uses a `Callout`:

<CodeBlock title="content/pages/home.mdx">

```mdx
<Callout title="Heads up">Prices change on 1 March.</Callout>
```

</CodeBlock>

And this renders it:

<CodeBlock title="components/document-body.tsx">

```tsx
import type { ReactNode } from "react";
import { MdxBody } from "@usegraft/sdk-next";

const components = {
  Callout: ({ title, children }: { title?: string; children: ReactNode }) => (
    <aside className="callout">
      {title && <strong>{title}</strong>}
      {children}
    </aside>
  ),
};

export function DocumentBody({ source }: { source: string }) {
  return <MdxBody source={source} components={components} />;
}
```

</CodeBlock>

<Callout label="Content cannot run code" type="note">
  By default `<MdxBody />` refuses `{…}` expressions, `import`, and `export`,
  because those would run as JavaScript on your server. Components with plain
  string attributes, like the `Callout` above, are allowed. See
  [MDX safety](/docs/mdx-safety).
</Callout>

## Serve functions and MCP from your app

<TierBadge tier="postgres" />

Skip this section unless you need it. Mount these routes when you want to:

- call your [typed functions](/docs/functions-and-access) at
  `POST /api/fn/<name>`, or
- let remote agents read and write content over MCP at `POST /api/mcp`.

Both need the Postgres engine and two more packages:

```sh
npm i @usegraft/auth @usegraft/mcp
```

Both routes need to know who is calling. This resolver accepts one token from
your environment, which is enough to try things out. [Auth](/docs/auth) shows
how to accept signed tokens from your identity provider.

<CodeBlock title="lib/actor.ts">

```ts
import { createActorResolver } from "@usegraft/auth";

export const actor = createActorResolver({
  devTokens: process.env.GRAFT_DEV_TOKEN
    ? {
        [process.env.GRAFT_DEV_TOKEN]: {
          kind: "human",
          id: "owner",
          scopes: ["content:write", "submissions:admin"],
        },
      }
    : undefined,
});
```

</CodeBlock>

<CodeBlock title="app/api/fn/[name]/route.ts">

```ts
import { createFunctionsHandler } from "@usegraft/core";
import { functions } from "@/graft.config";
import { actor } from "@/lib/actor";
import { db } from "@/lib/graft";

export const POST = createFunctionsHandler({ db, functions, actor });
```

</CodeBlock>

<CodeBlock title="app/api/mcp/route.ts">

```ts
import { createGraftMcpHandler } from "@usegraft/mcp";
import { collections, functions } from "@/graft.config";
import { actor } from "@/lib/actor";
import { db } from "@/lib/graft";

export const POST = createGraftMcpHandler({
  contentDir: "./content",
  db,
  collections,
  functions,
  actor,
});
```

</CodeBlock>

A request without a valid token gets a `401`. Never mount the MCP route with
`allowAnonymous: true` on a server that others can reach. For public,
read-only docs, use the [docs MCP](/docs/docs-mcp) instead.

## Refresh pages when content changes

<TierBadge tier="postgres" />

On the static engine, content changes ship with a new deploy, so there is
nothing to refresh. On Postgres, content can change while your app is running,
from Studio or from an agent. This section makes Next.js refresh only the pages
whose content changed.

It takes two steps. How you cache reads depends on your version. Next.js 16
uses cached functions. Next.js 14 and 15 use `unstable_cache`. The refresh
route is the same on all three.

<Steps>

<Step title="Tag each cached read">

Cache each read and tag it with `tagsFor`. Use these functions in your pages
instead of calling `graft` directly.

<Tabs labels="Next.js 16, Next.js 14 and 15">

<Tab>

Turn on cached functions:

<CodeBlock title="next.config.ts">

```ts
const nextConfig: NextConfig = {
  cacheComponents: true,
};
```

</CodeBlock>

Then wrap each read in a `'use cache'` function:

<CodeBlock title="lib/content.ts">

```ts
import { cacheTag } from "next/cache";
import { tagsFor } from "@usegraft/sdk-next";
import { graft } from "@/lib/graft";

export async function getPage(slug: string) {
  "use cache";
  cacheTag(...tagsFor("main", "pages", slug));
  return graft.getContent("pages", slug);
}

export async function listPages() {
  "use cache";
  cacheTag(...tagsFor("main", "pages"));
  return graft.listContent("pages");
}
```

</CodeBlock>

</Tab>

<Tab>

Wrap each read in `unstable_cache` and pass the tags:

<CodeBlock title="lib/content.ts">

```ts
import { unstable_cache } from "next/cache";
import { tagsFor } from "@usegraft/sdk-next";
import { graft } from "@/lib/graft";

export function getPage(slug: string) {
  return unstable_cache(() => graft.getContent("pages", slug), ["graft", "pages", slug], {
    tags: tagsFor("main", "pages", slug),
  })();
}

export const listPages = unstable_cache(() => graft.listContent("pages"), ["graft", "pages"], {
  tags: tagsFor("main", "pages"),
});
```

</CodeBlock>

`unstable_cache` stores results as JSON, so a cached document's `updatedAt`
comes back as a string. Wrap it in `new Date()` before you use it as a date.

</Tab>

</Tabs>

Without this step, `revalidateContent` has nothing to refresh and does
nothing.

</Step>

<Step title="Add a route that refreshes what changed">

`revalidateContent` takes the list of documents a compile changed and refreshes
the matching tags: each changed document, and the collection it is in.

<CodeBlock title="app/api/revalidate/route.ts">

```ts
import { revalidateContent, type ChangeSet } from "@usegraft/sdk-next";

function isChangeSet(value: unknown): value is ChangeSet {
  const v = value as Partial<ChangeSet> | null;
  return Array.isArray(v?.added) && Array.isArray(v?.changed) && Array.isArray(v?.removed);
}

export async function POST(request: Request) {
  const secret = process.env.GRAFT_WEBHOOK_SECRET;
  if (!secret || request.headers.get("authorization") !== `Bearer ${secret}`) {
    return Response.json({ error: "Unauthorized" }, { status: 401 });
  }

  const body = await request.json().catch(() => null);
  if (!isChangeSet(body?.changes)) {
    return Response.json({ error: "Send { branch, changes }." }, { status: 400 });
  }

  const tags = revalidateContent(body.branch ?? "main", body.changes);
  return Response.json({ revalidated: tags });
}
```

</CodeBlock>

</Step>

</Steps>

Graft does not call this route for you. Call it after content changes, with
the change list Graft gave you. An agent's `write_content` call returns it as
`changes`, shaped like this:

```json
{
  "branch": "main",
  "changes": { "added": ["pages/pricing"], "changed": ["pages/home"], "removed": [], "unchanged": 12 }
}
```

To refresh inside the same request instead, for example from a Server Action
that saves and then shows the result, use `updateContent(branch, changes)`.
It needs Next.js 16. On 14 and 15 it throws an error that points you back to
`revalidateContent`.
