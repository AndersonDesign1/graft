<p className="kicker">Go from an empty folder to your content on a page in about 10 minutes.</p>

In this guide you will:

- Set up Graft in a project with `graft init`
- Compile your content, which checks each file and builds the index your app
  reads from
- Read a document in your app, with full TypeScript types

## Before you start

You need **Node.js 22.16 or newer**. Graft's static index uses the `node:sqlite`
module that ships with it. You do not need a database or a cloud account.

  "Add Graft to this project following https://graft.page/docs/getting-started.md.

## Set up your first project

Pick the tab that matches your project. Each one runs the same three steps:
set up, compile, read. The Next.js and Astro paths end with a rendered page.
The plain TypeScript path prints the document in your terminal, with no
framework involved. Other frameworks are listed [after the tabs](#your-framework).

<Tabs labels="Next.js, Plain TypeScript, Astro">

<Tab>

### Next.js (App Router)

Goal: render a compiled document in a Server Component.

<Steps>

<Step title="Install the Next.js SDK and CLI">

The SDK needs Next.js 15.5.24 or newer on 15, or 16.3.3 or newer on 16. Check
yours with `npx next --version`, and upgrade first if it is older.

```sh
npm i @usegraft/sdk-next @usegraft/db
npm i -D @usegraft/cli
```

</Step>

<Step title="Initialize Graft">

```sh
npx @usegraft/cli@latest init
```

This scaffolds `graft.config.ts`, creates sample content in `content/pages/home.mdx`,
and sets up the static index.

</Step>

<Step title="Compile your content">

```sh
npx graft compile
```

This validates your markdown files against the schema and writes an embedded
SQLite index to `.graft/index.db`. The index is derived state: your files in
Git stay authoritative, and recompiling rebuilds it at any time.

</Step>

<Step title="Create the Graft client">

The client is the object your pages read through. Create it once, in its own
module, so every page shares it:

<CodeBlock title="lib/graft.ts">

```ts
import { openStaticIndex } from "@usegraft/db";
import { createGraft } from "@usegraft/sdk-next";
import { collections } from "@/graft.config";

export const graft = createGraft({
  index: await openStaticIndex(".graft/index.db"),
  collections,
});
```

</CodeBlock>

It lives outside `app/` on purpose. A Next.js page file may only export the
page and its route options, so a client exported from `app/page.tsx` fails the
build's type check.

</Step>

<Step title="Read content in a Server Component">

Replace `app/page.tsx` to read the sample page and render it:

<CodeBlock title="app/page.tsx">

```tsx
import { MdxBody } from "@usegraft/sdk-next";
import { notFound } from "next/navigation";
import { graft } from "@/lib/graft";

export default async function Page() {
  const home = await graft.getContent("pages", "home");
  if (!home) notFound();

  return (
    <main>
      <h1>{home.data.title}</h1>
      <p>{home.data.tagline}</p>
      <MdxBody source={home.body} />
    </main>
  );
}
```

</CodeBlock>

`home.data` is typed from your schema: hover `title` in your editor and you
will see `string`. `MdxBody` renders the Markdown body on the server.

Start your dev server and open `http://localhost:3000`:

```sh
npm run dev
```

You should see the heading **Hello, Graft**, its tagline, and the body text
from `content/pages/home.mdx`. Edit that file, run `npx graft compile` again,
and refresh to see the change.

</Step>

</Steps>

</Tab>

### Plain TypeScript (No Framework)

Goal: read a compiled document from a script, with no framework involved.

<Steps>

<Step title="Scaffold a project folder">

```sh
mkdir my-graft-site && cd my-graft-site
npm init -y
npm pkg set type=module
npm i @usegraft/db @usegraft/sdk-core
npm i -D @usegraft/cli tsx typescript @types/node
npx @usegraft/cli@latest init
```

`type=module` makes the project an ES module, so the script in the last step
can use `await` at the top level.

</Step>

<Step title="Compile content">

```sh
npx graft compile
```

This compiles `content/pages/home.mdx` into `.graft/index.db`.

</Step>

<Step title="Read and verify output">

Create `read.ts`:

<CodeBlock title="read.ts">

```ts
import { openStaticIndex } from "@usegraft/db";
import { createClient } from "@usegraft/sdk-core";
import { collections } from "./graft.config";

const index = await openStaticIndex(".graft/index.db");
const graft = createClient({ index, collections });

const home = await graft.getDocument("pages", "home");

console.log("Title:", home?.data.title);
console.log("Tagline:", home?.data.tagline);
```

</CodeBlock>

Without a framework you use `@usegraft/sdk-core` directly, whose read method is
`getDocument`. The framework packages wrap the same call and name it
`getContent`. Both return the same typed document.

Run the script:

```sh
npx tsx read.ts
```

You will see the values from `content/pages/home.mdx`:

```text
Title: Hello, Graft
Tagline: Content lives in git; the index is a file.
```

</Step>

</Steps>

</Tab>

## Add your own content

Each document is a file at `content/<collection>/<slug>.mdx`:

- A **collection** is a named group of documents, like `pages`. Its fields are
  declared in `graft.config.ts`.
- The **slug** is the document's name inside the collection. `content/pages/about.mdx`
  has the slug `about`.
- **Frontmatter** is the block between the `---` lines at the top. Its fields
  must match the collection's schema, or the compile stops and says which field
  is wrong.
- The rest of the file is the body, in Markdown or MDX (Markdown that can
  include components).

Create `content/pages/about.mdx`:

<CodeBlock title="content/pages/about.mdx">

```mdx
---
title: About us
tagline: We build with code and AI agents.
---

Welcome! This page lives in Git, next to your code.
```

</CodeBlock>

Then compile again, or leave `graft dev` running so it recompiles whenever a
file changes:

```sh
npx graft compile    # compile once
npx graft dev        # recompile on every change
```

Read it the same way you read `home`: `graft.getContent("pages", "about")`.

## When you need Postgres

The project you just made uses the static engine, which needs nothing running.
Move to Postgres when users of your site write data at runtime, such as
comments, orders, or form submissions. Git cannot rebuild that data, so it
needs a database. Preview branches need Postgres too.

Switching is one line in `graft.config.ts` (`export const index = "postgres"`)
plus a database URL. [Storage engines](/docs/tiers) walks you through it.

## If something goes wrong

These are the errors people hit most often while getting started:

| Error code | What it means | What to do |
| :--- | :--- | :--- |
| `STATIC_INDEX_NOT_FOUND` | Your app read the index before it was compiled | Run `npx graft compile`, then start your app |
| `STATIC_INDEX_UNSUPPORTED` | Your Node.js version is older than 22.16 | Upgrade Node.js |
| `SCHEMA_VALIDATION_FAILED` | A file's frontmatter does not match its schema | The message names the file and field. Fix it and compile again |
| `NEEDS_DATABASE` | Your config uses a feature that needs Postgres | See [When you need Postgres](#when-you-need-postgres) |

Every error also prints a `fix` line with the exact next step. The
[Error reference](/docs/errors) explains all of them.
