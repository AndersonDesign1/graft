<p className="kicker">Read Graft content in TanStack Start through server functions.</p>

This guide adds Graft to a TanStack Start project. You read content
through server functions, so the database or index file never reaches the
browser, and you can serve Graft's functions and MCP endpoint from server routes.

**Before you start**, you need a TanStack Start project and a
`graft.config.ts` with compiled content. If you do not have those yet, run
through [Getting started](/docs/getting-started) first.

<Callout label="Prefer to let your agent do it?" type="note">
  Paste this into your coding agent: "Add Graft to this TanStack Start app following https://graft.page/docs/tanstack-start.md. Create the client in src/lib/graft.server.ts and read content through a createServerFn, never in a route loader."
</Callout>

Create the client once in a server-only module, then reach it from server
functions and server routes.

## Create the Graft client

<CodeBlock title="src/lib/graft.server.ts">

```ts
import { createDb } from "@usegraft/db";
import { createGraft } from "@usegraft/sdk-tanstack-start";
import { collections } from "../../graft.config";

export const db = createDb(process.env.DATABASE_URL!).db;
export const graft = createGraft({ db, collections });
```

</CodeBlock>

Static index instead of Postgres:

```ts
import { openStaticIndex } from "@usegraft/db";

export const graft = createGraft({
  index: await openStaticIndex(".graft/index.db"),
  collections,
});
```

<Callout label="Do not read in a route loader" type="warning">
  A route `loader` is the wrong place for this client. TanStack Start loaders
  are **isomorphic**: they run on the server for the first paint and in the
  browser on client-side navigation. A client that holds a database connection
  belongs in neither the client bundle nor the browser, which is what
  `createServerFn` is for.
</Callout>

## Read a document

<CodeBlock title="src/routes/docs.$slug.tsx">

```ts
import { createServerFn } from "@tanstack/react-start";
import { graft } from "../lib/graft.server";

const getDoc = createServerFn({ method: "GET" })
  .validator((slug: string) => slug)
  .handler(({ data: slug }) => graft.getContent("docs", slug));
```

</CodeBlock>

Each call reads the index. If one request reads the same document in several
places, cache the result yourself.

## Serve functions and MCP from your app

This step is optional, and it needs the Postgres engine. It needs three more
packages:

```sh
npm i @usegraft/core @usegraft/auth @usegraft/mcp
```

Copy these mounts as written. The server-route factory name has moved across
TanStack Start releases; the handler signature has not.

<CodeBlock title="src/routes/api/fn/$name.ts">

```ts
import { createServerFileRoute } from "@tanstack/react-start/server";
import { createFunctionsHandler } from "@usegraft/core";
import { graftRoute } from "@usegraft/sdk-tanstack-start";
import { functions } from "../../../graft.config";
import { db } from "../../lib/graft.server";

const handler = createFunctionsHandler({ db, functions });

export const ServerRoute = createServerFileRoute("/api/fn/$name").methods({
  POST: graftRoute(handler),
  GET: graftRoute(handler), // 405s with Allow and a fix
});
```

</CodeBlock>

<CodeBlock title="src/routes/api/mcp.ts">

```ts
import { createActorResolver } from "@usegraft/auth";
import { createServerFileRoute } from "@tanstack/react-start/server";
import { createGraftMcpHandler } from "@usegraft/mcp";
import { graftRoute } from "@usegraft/sdk-tanstack-start";
import { collections, functions } from "../../graft.config";
import { db } from "../lib/graft.server";

// A dev token never expires, so it is accepted only in development. An unset
// NODE_ENV counts as production, so a deploy that forgets it stays closed.
const devToken = process.env.NODE_ENV === "development" ? process.env.GRAFT_DEV_TOKEN : undefined;

const actor = createActorResolver({
  issuers: (process.env.GRAFT_TRUSTED_ISSUERS ?? "")
    .split(/[,\s]+/)
    .filter(Boolean)
    .map((issuer) => ({ issuer })),
  devTokens: devToken
    ? {
        [devToken]: {
          kind: "human",
          id: "owner",
          scopes: ["content:write"],
        },
      }
    : undefined,
});

export const ServerRoute = createServerFileRoute("/api/mcp").methods({
  POST: graftRoute(
    createGraftMcpHandler({
      contentDir: "./content",
      db,
      collections,
      functions,
      actor,
    }),
  ),
});
```

</CodeBlock>

This endpoint serves content writes and asset uploads. JWT verification runs
only when `issuers` is passed; the library does not read
`GRAFT_TRUSTED_ISSUERS` (`graft serve` does). See [Auth](/docs/auth).
Unauthenticated callers get 401. `allowAnonymous: true` is only for a
loopback local server. Never anything reachable from a network. A public
docs surface is [`createDocsMcpHandler`](/docs/docs-mcp), which has no write
tools and no anonymous opt-in.

The parameter is typed structurally as `{ request: Request }`, so this package
needs no `@tanstack/react-start` dependency.

## Refresh pages when content changes

<TierBadge tier="postgres" />

On the static engine, content changes ship with a new deploy, so there is
nothing to refresh. On Postgres, content can change while your app is running,
from Studio or from an agent. TanStack Start has no tag-based data cache, so let your
CDN cache pages and purge only the ones whose content changed.

First, send each page with a header that lists the content it read. `tagsFor`
builds that list:

```ts
import { createServerFn } from "@tanstack/react-start";
import { setResponseHeader } from "@tanstack/react-start/server";
import { tagsFor } from "@usegraft/sdk-tanstack-start";
import { graft } from "../lib/graft.server";

const getDoc = createServerFn({ method: "GET" })
  .validator((slug: string) => slug)
  .handler(({ data: slug }) => {
    setResponseHeader("Cache-Tag", tagsFor("main", "docs", slug).join(","));
    return graft.getContent("docs", slug);
  });
```

The header goes on whichever response ran the function. On a full page load
that is the page's HTML. On client-side navigation, the browser calls the
server function directly, so it is that `GET` response. Let your CDN cache both:
they carry the same tags, so one purge refreshes both.

Then, when content changes, purge those tags at your CDN.
`tagsForChanges(branch, changes)` turns a change list into the tags to purge:
each changed document, and the collection it is in. Graft does not purge your
CDN for you. Do it from your own route, called with the change list.

The change list comes from two places. An agent's `write_content` call returns
it as `changes`. `graft compile --json` prints it too, along with the branch.
In a deploy script, send it to your route. The script stops if the compile
fails, and `--fail` makes a refused request fail the script too:

```sh
graft compile --json > changes.json || exit 1
curl --fail -X POST https://example.com/api/revalidate \
  -H "Authorization: Bearer $GRAFT_WEBHOOK_SECRET" \
  -H "content-type: application/json" \
  --data-binary @changes.json
```

Your route reads `branch` and `changes` from the body and passes them to
`tagsForChanges`.

`Cache-Tag` is the header Cloudflare reads, with tags separated by commas.
Fastly reads `Surrogate-Key`, with tags separated by spaces. Use the header
your CDN expects.
