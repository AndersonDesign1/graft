<p className="kicker">Describe your content once, and get types everywhere from it.</p>

The schema says what fields each kind of content has: a page has a title and
an optional tagline, a product has a name and a price. You write it once, in
`graft.config.ts`, and Graft uses it in three places:

- `graft compile` checks every file against it, and stops with a clear error
  when one does not match.
- [Typed functions](/docs/functions-and-access) check their inputs against it.
- Every read in your app is typed from it, so your editor knows each field.

It is built on [Zod](https://zod.dev), a TypeScript validation library, so
there is no code generation step. This page declares a collection, shows the
file and the typed read that go with it, and lists every field type.

## Declare a collection

A **collection** is a group of documents with the same fields, stored in
`content/<collection name>/`:

<CodeBlock title="graft.config.ts">

```ts
import { defineCollection, field } from "@usegraft/core";

export const pages = defineCollection({
  name: "pages",
  description: "Marketing and site pages.",
  fields: {
    title: field.string({ maxLength: 120, description: "Headline and <title>." }),
    tagline: field.string({ optional: true }),
    image: field.asset({ optional: true }),
  },
});
```

</CodeBlock>

The `description`s are for agents. An agent that calls `describe_schema` reads
them to learn what each collection and field is for, so write them as you would
explain the field to a new teammate.

## What a matching file looks like

Each document is a file whose frontmatter matches the fields:

<CodeBlock title="content/pages/about.mdx">

```mdx
---
title: About us
tagline: We build with code and AI agents.
---

The body is Markdown or MDX.
```

</CodeBlock>

And your app reads it with full types:

```ts
const about = await graft.getContent("pages", "about");
about?.data.title;   // string
about?.data.tagline; // string | undefined
about?.data.color;   // TypeScript error: pages has no field "color"
```

## What happens when a file does not match

If a file is missing a required field, or a value has the wrong type or is too
long, `graft compile` stops with `SCHEMA_VALIDATION_FAILED`. The message names
the file and the field, so you know exactly what to fix. Nothing is written to
the index until every file passes.

## Choose a field type

| Builder | Holds | Use it for |
| --- | --- | --- |
| `field.string()` | A short string | Titles, names, slugs |
| `field.text()` | A long string | Summaries and longer text |
| `field.number()` | A number | Prices, quantities, ratings |
| `field.boolean()` | `true` or `false` | Flags such as `featured` |
| `field.datetime()` | An ISO date and time | Publish dates |
| `field.asset()` | `{ key, alt? }` | Images and files. See [Assets](/docs/assets) |
| `field.object({ fields })` | A nested group of fields | An author with a name and a URL |
| `field.array({ of })` | A list of another field | Tags, FAQ entries |
| `field.json()` | Any JSON value | A last resort. Prefer an object or array, which are checked and typed |

Every builder accepts `optional: true` and a `description`.

## Limit what a field accepts

| Option | Applies to | Effect |
| --- | --- | --- |
| `maxLength` | `string`, `text` | The longest allowed value |
| `pattern` | `string`, `text` | A regular expression the value must match |
| `min`, `max` | `number` | The allowed range |
| `int: true` | `number` | Whole numbers only |
| `maxItems` | `array` | The most entries allowed |

Set `maxLength` on any string a public form writes to, and `maxItems` on any
array, so one request cannot store megabytes. Set `max` on numbers that get
multiplied, such as a quantity times a price. `field.json()` has no size limit,
so keep it out of public forms.

## Nest fields

Combine `field.array` and `field.object` for repeated groups, such as FAQ
entries:

```ts
faqs: field.array({
  of: field.object({
    fields: {
      question: field.string(),
      answer: field.text(),
    },
  }),
  optional: true,
}),
```

## Export your collections

Your config must export `collections`, and `functions` if you define any. The
CLI loads the file directly, so there is no build step, and your app imports
the same file for its typed reads.

If you added ready-made features with `graft add`, combine them with your own
collections using `mergePrimitives`:

<CodeBlock title="graft.config.ts">

```ts
import { mergePrimitives } from "@usegraft/core";
import * as primitives from "./graft";

export const { collections, functions } = mergePrimitives([
  { collections: { pages }, functions: {} },
  primitives,
]);
```

</CodeBlock>

Two collections or functions with the same name stop the config from loading
with `CONFIG_INVALID`. Nothing is overridden silently.
[Owned primitives](/docs/owned-primitives) covers `graft add`.
