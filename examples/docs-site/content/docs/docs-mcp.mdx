<p className="kicker">Let anyone's agent read your published docs, with no login.</p>

If your Graft project hosts documentation, people will ask their coding agents
about it. A public docs endpoint lets those agents search and read your docs
directly, instead of scraping web pages. It is read-only and needs no
authentication.

It is a separate server from your project's main MCP endpoint, not a setting on
it:

| Endpoint | Surface | Auth |
| --- | --- | --- |
| `POST /api/mcp` | Everything an agent can do | Required |
| `POST /mcp` | Documentation only | None |

## Why a separate endpoint

Docs platforms already publish this shape, and agents arrive expecting it.
Mintlify generates a docs MCP at `/mcp` for every site it hosts: public,
unauthenticated, strictly read-only. Cloudflare runs a documentation server
separately from its authenticated API server.

Keeping it separate also keeps it safe. If it were a flag on the main endpoint,
which also handles writes, one wrong setting could publish more than your docs.
As its own server, it can only ever serve the tools listed below.

## What it serves

Five tools and the document resources.

| Tool | Purpose |
| --- | --- |
| `list_collections` | What kinds of documents exist |
| `list_content` | The documents in one collection |
| `get_content` | One document's frontmatter and body |
| `search_content` | Full-text search across the published content |
| `explain_error` | What a Graft error code means |

Documents are also addressable as
`graft://<branch>/<collection>/<slug>` resources, so a client can attach a page
rather than paste it.

## What it leaves out, and why

The exclusions are mostly not about writes, which is the part worth
understanding.

| Left out | Reason |
| --- | --- |
| `describe_schema` | Carries the project's functions |
| `list_registry`, `describe_item` | Carry the project's owned primitives |
| `list_branches`, `list_compilations`, `list_approvals` | Carry the project's operations |
| `graft://<branch>/schema` | Same payload as `describe_schema` |
| Prompts | Three of the four instruct `write_content`, which is not here |
| `write_content`, `delete_content`, `put_asset`, `run_function`, `decide_approval` | Writes and execution |

Every item in the first three rows is a read. That is exactly why "read-only" is
the wrong test for what belongs on a public endpoint.

## Set one up

`createDocsMcpHandler` returns the same `Request → Response` handler shape as
the private one.

<CodeBlock title="src/pages/mcp.ts" note="Astro">

```ts
import type { APIRoute } from "astro";
import { resolve } from "node:path";
import { createDb } from "@usegraft/db";
import { createDocsMcpHandler, type GraftMcpHandler } from "@usegraft/mcp";
import { collections } from "../../graft.config";

let handler: GraftMcpHandler | null = null;

function getHandler(): GraftMcpHandler {
  if (!handler) {
    handler = createDocsMcpHandler({
      name: "graft-docs",
      contentDir: resolve(process.cwd(), "content"),
      collections,
      db: createDb(process.env.DATABASE_URL as string).db,
    });
  }
  return handler;
}

export const POST: APIRoute = ({ request }) => getHandler()(request);
export const GET: APIRoute = ({ request }) => getHandler()(request);
```

</CodeBlock>

Mount it at `/mcp` on the docs domain. That is where clients look.

Both methods are exported because the transport is stateless and POST-only. The
`GET` export exists so the route answers 405 with `Allow` rather than 404, which
tells a client the endpoint is real and speaks a POST-only transport.

### It cannot be widened

`DocsMcpOptions` accepts only `contentDir`, `collections`, `db`,
`staticIndexPath`, `branchId`, `scope`, `name`, and `version`. There is no
`functions`, no `actor`, no asset store, no approval elicitation, and no
`allowAnonymous`.

Omitting them from the type is what keeps them from being configured by
accident. A JavaScript caller who passes `functions` anyway gets it dropped at
runtime, not merely unregistered. That distinction is what the test asserts.

Standing up the public endpoint cannot open the private one.

## Choose what is published

The server publishes the collections you hand it. To publish your docs but not
your product catalog, pass only the collections you mean:

```ts
createDocsMcpHandler({
  contentDir,
  collections: { docs },
  db,
});
```

Remember that `get_content` and `list_content` read the authored files, so
anything in a published collection's directory is published, including drafts
you have not linked from anywhere.

## Other ways agents can read your docs

An MCP endpoint is one of several ways an agent can read documentation without
scraping rendered HTML. This site also serves:

| Surface | What it is |
| --- | --- |
| `/llms.txt` | An index of pages with descriptions and `.md` links |
| `/llms-full.txt` | Every page's content in one file |
| `/docs/<slug>.md` | Any page as markdown |

Those are generated from the content index and the sidebar's own grouping, so
they cannot drift from the nav.

<Callout label="In the dev server" type="note">
  `/llms.txt` is shadowed under `astro dev`, because Vite serves the project
  root as static and a Graft project has an `llms.txt` at its root. Production
  is correct. Verify that route with `astro build`, not the dev server.
</Callout>
