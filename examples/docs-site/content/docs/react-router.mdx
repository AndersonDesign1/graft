<p className="kicker">Read Graft content in React Router framework mode.</p>

This guide adds Graft to a React Router app in framework mode. You read
content in route loaders on the server, and you can serve Graft's functions and
MCP endpoint from resource routes.

**Before you start**, you need a React Router app in framework mode and a
`graft.config.ts` with compiled content. If you do not have those yet, run
through [Getting started](/docs/getting-started) first.

<Callout label="Prefer to let your agent do it?" type="note">
  Paste this into your coding agent: "Add Graft to this React Router app following https://graft.page/docs/react-router.md. Create the client in app/lib/graft.server.ts and read the pages collection in a route loader."
</Callout>

For framework mode, which is where React Router runs loaders and actions on a
server. Create the client once in a `.server.ts` module.

## Create the Graft client

<CodeBlock title="app/lib/graft.server.ts">

```ts
import { createDb } from "@usegraft/db";
import { createGraft } from "@usegraft/sdk-react-router";
import { collections } from "../../graft.config";

export const db = createDb(process.env.DATABASE_URL!).db;
export const graft = createGraft({ db, collections });
```

</CodeBlock>

Static index instead of Postgres:

```ts
import { openStaticIndex } from "@usegraft/db";

export const graft = createGraft({
  index: await openStaticIndex(".graft/index.db"),
  collections,
});
```

## Read a document

<CodeBlock title="app/routes/docs.$slug.tsx">

```ts
import { graft } from "../lib/graft.server";
import type { Route } from "./+types/docs.$slug";

export async function loader({ params }: Route.LoaderArgs) {
  return { doc: await graft.getContent("docs", params.slug) };
}
```

</CodeBlock>

`loader` and `action` run on the server and React Router strips them from the
browser bundle. The `.server.ts` name is belt and braces on top of that: it
turns a stray client import into a build error rather than a database URL in
a bundle.

To read content in the browser (a search box, an editor preview), use
[the React adapter](/docs/react).

## Serve functions and MCP from your app

This step is optional: it needs the Postgres engine and three more packages:

```sh
npm i @usegraft/core @usegraft/auth @usegraft/mcp
```

`graftRoute` binds a Graft handler to a resource route. That is a route module with
no default export, whose loader and action return raw Responses.

<CodeBlock title="app/routes/api.fn.$name.ts">

```ts
import { createFunctionsHandler } from "@usegraft/core";
import { graftRoute } from "@usegraft/sdk-react-router";
import { functions } from "../../graft.config";
import { db } from "../lib/graft.server"; // export the same db you passed to createGraft

const handler = createFunctionsHandler({ db, functions });

export const action = graftRoute(handler); // POST
export const loader = graftRoute(handler); // GET, which 405s with Allow and a fix
```

</CodeBlock>

<CodeBlock title="app/routes/api.mcp.ts">

```ts
import { createActorResolver } from "@usegraft/auth";
import { createGraftMcpHandler } from "@usegraft/mcp";
import { graftRoute } from "@usegraft/sdk-react-router";
import { collections, functions } from "../../graft.config";
import { db } from "../lib/graft.server";

// A dev token never expires, so it is accepted only in development. An unset
// NODE_ENV counts as production, so a deploy that forgets it stays closed.
const devToken = process.env.NODE_ENV === "development" ? process.env.GRAFT_DEV_TOKEN : undefined;

const actor = createActorResolver({
  issuers: (process.env.GRAFT_TRUSTED_ISSUERS ?? "")
    .split(/[,\s]+/)
    .filter(Boolean)
    .map((issuer) => ({ issuer })),
  devTokens: devToken
    ? {
        [devToken]: {
          kind: "human",
          id: "owner",
          scopes: ["content:write"],
        },
      }
    : undefined,
});

export const action = graftRoute(
  createGraftMcpHandler({
    contentDir: "./content",
    db,
    collections,
    functions,
    actor,
  }),
);
```

</CodeBlock>

This endpoint serves content writes and asset uploads. JWT verification runs
only when `issuers` is passed; the library does not read
`GRAFT_TRUSTED_ISSUERS` (`graft serve` does). See [Auth](/docs/auth).
Unauthenticated callers get 401. `allowAnonymous: true` is only for a
loopback local server. Never anything reachable from a network. A public
docs surface is [`createDocsMcpHandler`](/docs/docs-mcp), which has no write
tools and no anonymous opt-in.

Register them the way you register any route:

<CodeBlock title="app/routes.ts">

```ts
import { route, type RouteConfig } from "@react-router/dev/routes";

export default [
  route("api/fn/:name", "routes/api.fn.$name.ts"),
  route("api/mcp", "routes/api.mcp.ts"),
] satisfies RouteConfig;
```

</CodeBlock>

<Callout label="Why the route exports a loader" type="warning">
  React Router handles GET requests with a route's `loader` export and all
  other methods with its `action` export, so the same Graft handler is
  exported twice. Keep the `loader` export even though functions are called
  with POST. Without it, a GET to a function URL gets React Router's generic
  "no loader" error. With it, the caller gets Graft's 405 response, which says
  which method to use.
</Callout>

## Refresh pages when content changes

<TierBadge tier="postgres" />

On the static engine, content changes ship with a new deploy, so there is
nothing to refresh. On Postgres, content can change while your app is running,
from Studio or from an agent. React Router has no tag-based data cache, so let your
CDN cache pages and purge only the ones whose content changed.

First, send each page with a header that lists the content it read. `tagsFor`
builds that list:

```ts
import { tagsFor } from "@usegraft/sdk-react-router";
import type { Route } from "./+types/docs.$slug";

export function headers({ params }: Route.HeadersArgs) {
  return { "Cache-Tag": tagsFor("main", "docs", params.slug).join(",") };
}
```

Then, when content changes, purge those tags at your CDN.
`tagsForChanges(branch, changes)` turns a change list into the tags to purge:
each changed document, and the collection it is in. Graft does not purge your
CDN itself. Add a route that reads `branch` and `changes` from a POST body,
checks a bearer secret, and purges the tags `tagsForChanges` returns.

Then point Graft at the route. Add two variables to the `.env` Graft reads, or to the environment, wherever
`graft serve`, `graft studio`, `graft mcp`, `graft merge` or `graft migrate`
runs. The secret must match the one the route checks:

<CodeBlock title=".env">

```sh
GRAFT_REVALIDATE_URL=https://example.com/api/revalidate
GRAFT_WEBHOOK_SECRET=a-long-random-string
```

</CodeBlock>

Graft now calls the route after every write that changes content: an agent's
`write_content` or `delete_content`, a Studio save, compile or revert, and
`graft merge --apply` or `graft migrate --apply`. If the route fails, the write
still succeeds, and the server logs a `REVALIDATE_FAILED` error with the body to
resend. Recompiling does not resend it: a new compile reports those documents
as unchanged. If your app
mounts the MCP endpoint itself, pass `onContentChange` to
`createGraftMcpHandler` and purge there instead.

`graft compile` never calls the route: a deploy compiles before the new version
is live. To purge after a deploy, send the compile's output yourself. The script
stops if the compile fails, and `--fail` makes a refused request fail the
script too:

```sh
graft compile --json > changes.json || exit 1
curl --fail -X POST https://example.com/api/revalidate \
  -H "Authorization: Bearer $GRAFT_WEBHOOK_SECRET" \
  -H "content-type: application/json" \
  --data-binary @changes.json
```

`Cache-Tag` is the header Cloudflare reads, with tags separated by commas.
Fastly reads `Surrogate-Key`, with tags separated by spaces. Use the header
your CDN expects.
