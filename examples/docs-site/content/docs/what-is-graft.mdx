Graft is an open-source, self-hostable content management system designed for
modern developers and AI agents.

Instead of locking content inside a remote database or cloud dashboard, Graft
treats content as code: your articles and pages live as version-controlled MDX
files in Git. A single TypeScript schema validates your data and provides
complete end-to-end type safety for your frontend.

<Callout label="Beta Notice" type="note">
  These docs describe `1.0.0-beta.x`. The core architecture—content in Git,
  derived indexing, unified Zod schemas, and native MCP support—is settled.
  Minor improvements and fixes land between betas and are tracked in the
  changelog.
</Callout>

## The 30-second mental model

```text
┌────────────────────────┐      ┌────────────────────────┐      ┌────────────────────────┐
│   MDX Files in Git     │ ───► │     graft compile      │ ───► │  Typed Reads in App    │
│  content/pages/*.mdx   │      │  Validates & Projects  │      │  Next.js, Astro, React │
└────────────────────────┘      └────────────────────────┘      └────────────────────────┘
            ▲                                                                │
            │                                                                │
            └────────── AI Agents (MCP) & Developers (CLI / Git) ────────────┘
```

- **Author files in Git:** Write Markdown or MDX in your project's `content/`
  directory. Commit, branch, and review diffs using your standard Git workflow.
- **Compile a derived index:** `graft compile` validates your frontmatter
  against your schema and builds an instant, queryable index with full-text
  search.
- **Read typed data:** Framework SDKs (Next.js, Astro, SvelteKit, TanStack Start,
  React Router) provide fast, typed queries directly to your components.
- **Collaborate via MCP:** AI agents connect via Model Context Protocol (MCP) to
  draft content, search documents, and inspect schemas with built-in safety
  boundaries.

## Choosing your storage engine

Graft runs on two interchangeable storage engines with an identical authoring and reading API:

| Storage Engine | When to use | Infrastructure needed |
| :--- | :--- | :--- |
| **Static Engine** *(default)* | Blogs, documentation, marketing sites, portfolios | **None.** Runs off an embedded local SQLite file created at build time. |
| **Postgres Engine** | Sites with form submissions, comments, user orders, or preview branches | **Postgres.** Holds live operational data alongside the content index. |

Every project starts on the Static Engine by default. You can switch to the Postgres Engine with a single line in `graft.config.ts` whenever you need dynamic runtime data.
