Operational data (submissions, orders, anything Postgres owns) is only ever
touched through functions defined in `graft.config.ts`:

```ts
export const submitContact = defineFunction({
  name: "submitContact",
  kind: "mutation",
  public: true, // the explicit, greppable opt-out — see below
  rateLimit: { limit: 5, windowSeconds: 60 },
  input: submissions.fields,
  handler: async (ctx) => {
    const record = await insertRecord(ctx, submissions, ctx.input);
    return { id: record.id, receivedAt: record.createdAt.toISOString() };
  },
});
```

Functions are served at `POST /api/fn/name` (JSON object body) — mounted in
your app via the framework SDK, or by `graft serve` headless. Success returns
`{ data }`; failure returns a GraftError with a `fix`.

<Callout label="invariant">
  Every function is a **stateless Web-standard handler** (`Request →
  Response`). No long-running server owns a pool — which is why the same
  handlers run embedded in Next/Astro/SvelteKit, in a container, or on
  request-scoped compute, byte-for-byte identical.
</Callout>

## Secure by default

- **Mutations reject anonymous callers** unless the function says
  `public: true`. The default is deny.
- **`access`** replaces the default with your own rule —
  `access: requireScopes("submissions:read")` gates on token scopes.
- **Rate limits** are declarative (`rateLimit`) and counted against the audit
  log — stateless, no counter service.
- **Every invocation writes an `audit_log` row**: actor, correlation id, git
  SHA of the serving code.

## Who is calling

`@graft/auth` resolves the actor: OIDC-verified bearer tokens
(verify-don't-mint — Graft never issues identities) plus `GRAFT_DEV_TOKEN` as
a static local credential. No token → anonymous; a bad token → `TOKEN_INVALID`,
never a silent downgrade.

## Destructive operations

A function marked `destructive: true` is **always human-gated**, regardless of
any policy: calling it files an approval and returns 403 with the approval id;
a human runs `graft approve <id>`; the caller retries with the
`x-graft-approval` header. Approvals are one-shot and input-bound, and the
runtime credential can never approve its own requests — approval is an
operator action by construction.
