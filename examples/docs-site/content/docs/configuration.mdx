Commands and runtimes walk up from the working directory for `.env`.

## Required: none

A static project needs no environment at all. `graft init` scaffolds the static
index, `graft compile` writes `.graft/index.db`, and your app reads it embedded.
Everything below is for a capability you opt into.

## Postgres

Required once `graft.config.ts` sets `export const index = "postgres"`, which is
what operational data, typed functions, and copy-on-write branches need.

| Variable | Used by | Purpose |
| --- | --- | --- |
| `DATABASE_URL` | compile, dev, migrate, branch, merge, serve, app reads | Postgres connection |

## Identity and policy

| Variable | Purpose |
| --- | --- |
| `GRAFT_DEV_TOKEN` | Static bearer for local / bootstrap actors |
| `GRAFT_DEV_SCOPES` | Comma-separated scopes for the dev token |
| `GRAFT_TRUSTED_ISSUERS` | Comma-separated OIDC issuer URLs (discovery) |
| `GRAFT_MCP_ALLOW_ANONYMOUS` | `1` to serve anonymous MCP callers (local dev only; refused by default) |
| `GRAFT_APPROVAL_POLICY` | e.g. `human` to gate mutations by default at the handler |

## Serve

| Variable | Purpose |
| --- | --- |
| `PORT` / `HOST` | Bind for `graft serve` (default loopback `:3903`) |
| `GRAFT_HARDEN` | Container: create + harden the runtime role at boot, then serve under it. Default `1` in all-in-one, `0` in `GRAFT_MODE=serve` |
| `GRAFT_RUNTIME_PASSWORD` | The hardened role's password; setting it also turns hardening on. Generated per boot when unset |
| `GRAFT_MODE` | Container compose: `serve` against external db/storage |

## Assets (S3-compatible)

| Variable | Purpose |
| --- | --- |
| `S3_BUCKET` | Bucket name |
| `S3_ENDPOINT` | API endpoint (R2, MinIO, Tigris, …) |
| `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` | Credentials |
| `S3_PUBLIC_URL` | Optional stable public base; else presigned GET |
| `GRAFT_ENSURE_BUCKET` | Container: set `0` when the bucket already exists |

## Neon branching

| Variable | Purpose |
| --- | --- |
| `NEON_API_KEY` | Create / drop physical CoW branches |
| `GRAFT_NEON_PROJECT_ID` | Neon project id (required; keys may be project-scoped) |

## graft.config.ts exports

The config is TypeScript you own, loaded at runtime. Only `collections` is
required.

| Export | Default | Purpose |
| --- | --- | --- |
| `collections` | required | Record of `defineCollection` results |
| `functions` | `{}` | Record of `defineFunction` results; enables `list_functions` and `run_function` |
| `contentDir` | `"content"` | Content root, relative to the config file |
| `migrationsDir` | `"migrations"` | Migrations directory, relative to the config file |
| `index` | `"postgres"` | `"static"` for the zero-service tier |
| `mdxTrust` | `"restricted"` | How much of MDX an authored body may be |

### mdxTrust

`"restricted"` refuses `{…}` expressions, `import`, `export` and spread
attributes in authored bodies. `graft compile` checks every document and reports
all offenders at once, so the refusal happens at build time rather than
per-request.

Set `"full"` only when every author of the repository has commit access. Rendering
evaluates MDX as JavaScript on the server, so on a Studio hosted for writers,
"can author a page" would otherwise mean "can execute code on the render host".

```ts
// graft.config.ts
export const mdxTrust = "full";
```

`MdxBody` has its own `trust` prop with the same default, and the two have to
agree: set `mdxTrust` here and pass `trust="full"` at the render site. Compile
says so in the error when it refuses a document.

## Operator vs runtime

Keep two URLs in production:

1. **Operator** — compile, migrate, merge, approve (CI or your machine)
2. **Runtime** — `DATABASE_URL` for the deployment after `graft harden`

On Vercel embedded deploys, run compile in the build step with the operator URL,
then serve the app with the runtime URL. See [Deploy](/docs/deploy).
